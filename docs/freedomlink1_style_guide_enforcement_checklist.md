# ✦ Freedomlink1 Style Guide Enforcement Checklist

*Editorial Compliance — Epoch 6*

This checklist ensures every Freedomlink1 document complies with the [Sovereign Editorial Charter](freedomlink1_institutional_style_guide.md). Stewards must apply this checklist before committing any new governance, continuity, verification, hardware trust, economic, lineage, identity, automation, or stewardship artifact.

## ✦ 1. Sovereign Tone Compliance

Confirm the document uses:

- declarative, intentional language
- continuity-aware phrasing
- lineage-aligned framing
- authority-bounded statements
- verification-honest descriptions
- hardware-trust-aware language
- economic-continuity-aligned language

Reject if it contains:

- metaphor
- flourish
- emotional framing
- conversational looseness
- speculative language

## ✦ 2. Canonical Phrasing Compliance

Verify the document uses institutional phrasing where appropriate:

- “By authority of the Freedomlink1 Institution…”
- “I affirm sovereign identity provenance…”
- “I invoke Rootstone-I hardware trust binding…”
- “I acknowledge lineage continuity…”
- “I affirm alignment with PPTF Treasury Governance…”
- “I acknowledge that verification is limited to local artifacts…”
- “I declare the following action…”
- “I record this action across all required institutional surfaces…”
- “This ceremony does not grant authority.”
- “This verification does not validate runtime behavior.”

Reject if it uses non-canonical substitutes.

## ✦ 3. Structural Ritual Compliance

Verify the document follows the sovereign structure:

1. Invocation
2. Authority Evidence
3. Lineage
4. Identity
5. Hardware Trust
6. Economic Continuity
7. Verification Boundaries
8. Declaration
9. Multi-Surface Recording
10. Closure

Reject if sections are missing or reordered without justification.

## ✦ 4. Authority-Safe Language Compliance

Confirm the document never implies authority.

Reject if it uses verbs implying:

- enforcement
- attestation
- validation
- runtime correctness
- autonomous action
- implicit authorization

Accept only verbs such as:

- affirm
- acknowledge
- declare
- invoke
- record
- prepare
- reflect
- document
- align
- maintain

## ✦ 5. Verification-Safe Language Compliance

Confirm the document states verification boundaries clearly.

Accept only:

- “verifies local artifacts only”
- “does not validate runtime behavior”
- “records declared configuration”
- “updates `last_check` in the binding”
- “is a steward-initiated governed write”

Reject any implication of:

- runtime correctness
- chain-state correctness
- economic execution correctness
- hardware attestation
- identity attestation

## ✦ 6. Continuity-Safe Language Compliance

Confirm the document avoids implying autonomous epoch transitions.

Accept only:

- “prepares an epoch transition”
- “aligns continuity surfaces”
- “records continuity events”
- “acknowledges lineage anchors”

Reject:

- “performs an epoch transition”
- “advances the epoch”
- “executes continuity”

## ✦ 7. Hardware Trust Language Compliance

Confirm Rootstone-I is described as **declared**, not attested.

Accept:

- “declared hardware identity”
- “hardware trust invocation”
- “physical sovereignty binding”

Reject:

- “hardware attestation”
- “hardware verification”
- “hardware enforcement”

## ✦ 8. Economic Continuity Language Compliance

Confirm economic language preserves policy and execution boundaries.

Accept:

- “declared economic configuration”
- “economic continuity alignment”
- “treasury governance policy”

Reject:

- “economic correctness”
- “treasury execution validation”
- “runtime economic verification”

## ✦ 9. Formatting Compliance

Verify formatting rules:

- H1: document title
- H2/H3: section hierarchy
- single-level bullet lists
- no nested bullets
- code blocks for commands
- blockquotes for ceremony scripts
- approved section marker is restricted to section headings
- no emojis
- no conversational filler

Reject documents that violate formatting discipline.

## ✦ 10. Terminology Compliance

Verify consistent use of institutional terms:

- Steward
- Institution
- Unified Layer
- Root Build
- Epoch
- Continuity Surfaces
- Verification Surfaces
- Hardware Trust
- Economic Continuity
- Lineage Anchors

Reject inconsistent or undefined terminology.

## ✦ 11. Document Boundary Compliance

Confirm the document explicitly states:

- what it does
- what it does not do
- what authority it defers to
- what verification it cannot claim
- what runtime behavior it cannot imply
- what autonomous action it cannot perform

Reject documents lacking boundary declarations.

## ✦ 12. Sovereign Closure Compliance

Verify the closing block:

> Freedomlink1 Unified Layer  
> [Document Name] — Epoch 6

Reject documents without sovereign closure.

## ✦ Closing

This checklist supports compliance with the Sovereign Editorial Charter and preserves Freedomlink1’s institutional voice, authority boundaries, verification limits, continuity alignment, and sovereign identity.
