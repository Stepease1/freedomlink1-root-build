# ✦ Freedomlink1 Style Guide Quick-Reference Sheet

*Steward Rapid Guide — Epoch 6*

This sheet summarizes the Sovereign Editorial Charter, Enforcement Checklist, and Linting Ruleset. Use it while drafting any governance, continuity, verification, hardware trust, economic, lineage, identity, automation, or stewardship document.

## ✦ Sovereign Tone (Always Required)

Write with:

- declarative, intentional language
- continuity awareness
- lineage alignment
- authority boundaries
- verification honesty
- hardware trust awareness
- economic continuity alignment

Avoid:

- metaphor
- flourish
- emotional framing
- conversational looseness
- speculative language

## ✦ Canonical Phrasing (Use When Applicable)

Required institutional phrases:

- “By authority of the Freedomlink1 Institution…”
- “I affirm sovereign identity provenance…”
- “I invoke Rootstone-I hardware trust binding…”
- “I acknowledge lineage continuity…”
- “I affirm alignment with PPTF Treasury Governance…”
- “I acknowledge that verification is limited to local artifacts…”
- “I declare the following action…”
- “I record this action across all required institutional surfaces…”
- “This ceremony does not grant authority.”
- “This verification does not validate runtime behavior.”

Use exact wording.

## ✦ Structural Ritual (Document Layout)

Every major institutional document follows:

1. Invocation
2. Authority Evidence
3. Lineage
4. Identity
5. Hardware Trust
6. Economic Continuity
7. Verification Boundaries
8. Declaration
9. Multi-Surface Recording
10. Closure

Do not reorder or omit.

## ✦ Authority-Safe Language

Never imply authority.

Reject verbs like:

- authorize
- validate
- enforce
- attest
- guarantee
- certify

Use:

- affirm
- acknowledge
- declare
- invoke
- record
- prepare
- align
- maintain

Authority always requires **approval evidence**.

## ✦ Verification-Safe Language

Verification must state its limits.

Use:

- verifies local artifacts only
- does not validate runtime behavior
- records declared configuration
- updates `last_check`
- steward-initiated governed write

Reject any runtime correctness claims.

## ✦ Continuity-Safe Language

Avoid implying autonomous epoch transitions.

Reject:

- performs an epoch transition
- advances the epoch
- executes continuity

Use:

- prepares an epoch transition
- aligns continuity surfaces
- records continuity events
- acknowledges lineage anchors

## ✦ Hardware Trust Language

Rootstone-I is **declared**, not attested.

Reject:

- hardware attestation
- hardware verification
- hardware enforcement

Use:

- declared hardware identity
- hardware trust invocation
- physical sovereignty binding

## ✦ Economic Continuity Language

Economic continuity defines policy, not execution.

Reject:

- economic correctness
- treasury execution validation
- runtime economic verification

Use:

- declared economic configuration
- economic continuity alignment
- treasury governance policy

## ✦ Formatting Rules

- H1: document title
- H2: major sections
- H3: subsections
- single-level bullet lists only
- code blocks for commands
- blockquotes for ceremonies
- section marker permitted only in section headings
- no emojis
- no conversational filler

## ✦ Terminology Standards

Use institutional terms consistently:

- Steward
- Institution
- Unified Layer
- Root Build
- Epoch
- Continuity Surfaces
- Verification Surfaces
- Hardware Trust
- Economic Continuity
- Lineage Anchors

## ✦ Document Boundaries

Every document must state:

- what it does
- what it does not do
- what authority it defers to
- what verification it cannot claim
- what runtime behavior it cannot imply
- what autonomous action it cannot perform

## ✦ Sovereign Closure

End every document with:

> Freedomlink1 Unified Layer  
> [Document Name] — Epoch 6
