# ✦ Freedomlink1 Sovereign Editorial Charter

*Institutional Style Guide — Epoch 6*

The Sovereign Editorial Charter defines the writing voice, formatting conventions, authority boundaries, verification phrasing, and institutional tone used across all Freedomlink1 documents. It ensures every artifact reflects the institution’s sovereign identity, continuity awareness, and constitutional limits.

This charter applies to all governance, continuity, verification, hardware trust, economic, lineage, identity, automation, and stewardship documents.

## ✦ 1. Sovereign Tone

Freedomlink1 documents must speak with institutional gravitas.

Use a tone that is:

- declarative
- intentional
- continuity-aware
- lineage-aligned
- authority-bounded
- verification-honest
- hardware-trust-aware
- economic-continuity-aligned

Avoid:

- metaphor
- flourish
- emotional framing
- conversational looseness
- speculative language

The institution speaks with clarity, not persuasion.

## ✦ 2. Canonical Institutional Phrasing

Use these sovereign phrases consistently:

- **“By authority of the Freedomlink1 Institution…”**
- **“I affirm sovereign identity provenance…”**
- **“I invoke Rootstone-I hardware trust binding…”**
- **“I acknowledge lineage continuity…”**
- **“I affirm alignment with PPTF Treasury Governance…”**
- **“I acknowledge that verification is limited to local artifacts…”**
- **“I declare the following action…”**
- **“I record this action across all required institutional surfaces…”**
- **“This ceremony does not grant authority.”**
- **“This verification does not validate runtime behavior.”**

These phrases define the institution’s sovereign voice.

## ✦ 3. Structural Ritual

Freedomlink1 documents follow a sovereign structure:

1. Invocation
2. Authority Evidence Acknowledgment
3. Lineage Continuity
4. Identity Provenance
5. Hardware Trust Invocation
6. Economic Continuity Alignment
7. Verification Boundaries
8. Declaration of Action or Purpose
9. Multi-Surface Recording
10. Closure

This structure ensures institutional coherence across all layers.

## ✦ 4. Authority-Safe Language

Never imply authority where none exists.

Avoid verbs implying:

- enforcement
- attestation
- validation
- runtime correctness
- autonomous action
- implicit authorization

Use verbs that preserve constitutional boundaries:

- affirm
- acknowledge
- declare
- invoke
- record
- prepare
- reflect
- document
- align
- maintain

Authority is always tied to **approval evidence**, never ceremony or metadata.

## ✦ 5. Verification-Safe Language

Verification must always be described within its documented limits.

Use:

- “verifies local artifacts only”
- “does not validate runtime behavior”
- “records declared configuration”
- “updates `last_check` in the binding”
- “is a steward-initiated governed write”

Never imply:

- runtime correctness
- chain-state correctness
- economic execution correctness
- hardware attestation
- identity attestation

Verification preserves truth; it does not enforce it.

## ✦ 6. Continuity-Safe Language

Continuity documents must avoid implying autonomous epoch transitions.

Use:

- “prepares an epoch transition”
- “aligns continuity surfaces”
- “records continuity events”
- “acknowledges lineage anchors”

Avoid:

- “performs an epoch transition”
- “advances the epoch”
- “executes continuity”

Epoch transitions require governance approval evidence.

## ✦ 7. Hardware Trust Language

Rootstone-I must always be described as **declared**, not attested.

Use:

- “declared hardware identity”
- “hardware trust invocation”
- “physical sovereignty binding”

Avoid:

- “hardware attestation”
- “hardware verification”
- “hardware enforcement”

Hardware trust is invoked by stewards, not enforced by systems.

## ✦ 8. Economic Continuity Language

Economic documents must preserve the boundary between policy and execution.

Use:

- “declared economic configuration”
- “economic continuity alignment”
- “treasury governance policy”

Avoid:

- “economic correctness”
- “treasury execution validation”
- “runtime economic verification”

Economic continuity defines policy, not runtime behavior.

## ✦ 9. Formatting Conventions

Freedomlink1 documents must follow strict formatting rules:

- H1: Document Title
- H2: Major Sections
- H3: Subsections
- Single-level bullet lists
- No nested bullets
- Code blocks for commands
- Blockquotes for ceremony scripts
- No decorative symbols except the approved section marker
- No emojis
- No conversational filler

Documents must be clean, sovereign, and structured.

## ✦ 10. Terminology Standards

Use the following terms consistently:

- **Steward** — human authority
- **Institution** — Freedomlink1
- **Unified Layer** — documentation + verification + continuity
- **Root Build** — sovereign technical base
- **Epoch** — institutional time boundary
- **Continuity Surfaces** — continuity documentation
- **Verification Surfaces** — drift + integrity + binding
- **Hardware Trust** — Rootstone-I metadata
- **Economic Continuity** — PPTF Treasury Governance
- **Lineage Anchors** — declared genesis + continuity events

These terms define institutional identity.

## ✦ 11. Document Boundaries

Every Freedomlink1 document must explicitly state:

- what it does
- what it does not do
- what authority it defers to
- what verification it cannot claim
- what runtime behavior it cannot imply
- what autonomous action it cannot perform

This preserves institutional legitimacy.

## ✦ 12. Sovereign Closure

Documents must end with:

> Freedomlink1 Unified Layer  
> [Document Name] — Epoch 6

This marks the artifact as part of the institutional lineage.

Freedomlink1 Unified Layer  
Freedomlink1 Sovereign Editorial Charter — Epoch 6
